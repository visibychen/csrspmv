# v2.1: cost-guided direct CSR

`optimization/v2.1` is a child of v2 `9b652e8`. The original `csr.c` and the
v2 implementation remain unchanged. Default CLI kernel is still `original`.
Opt in with `--kernel=v2.1`; `--kernel=v2` remains available as a control.

## Usage and explicit calibration

```sh
OMP_NUM_THREADS=24 OMP_DYNAMIC=FALSE OMP_PLACES=cores \
OMP_PROC_BIND=spread OMP_WAIT_POLICY=PASSIVE \
./csrspmv A.mtx --matrix-format=f32 --source-vector-format=f32 \
  --destination-vector-format=f32 --kernel=v2.1 \
  --v21-profile=/absolute/path/profile.txt --repeat=9 -v
```

The profile is an external, frozen offline calibration artifact. This code
does not tune by running extra SpMV calls on the supplied matrix, inspect its
filename, cache Ax, or replace repeated additions by R*Ax. Without a profile,
or on a fingerprint mismatch, auto conservatively uses original CSR at the
requested team size, while charging its additional validation cost.

The experiment repository supplies `calibrate.c`, `fit_profile.py`, and the
generated profile. Twelve distinct generated shapes, a separate seed, six
team sizes (1/2/4/8/12/24), and rotated kernel order supply nonnegative least
squares coefficients. Calibration is not free; its duration and raw samples
are recorded separately from tasks that reuse that profile. It must be
regenerated for different compiler options/hardware/runtime settings.

The ABI-1 fingerprint covers the reported CPU model, GCC version, selected
compile feature macros, OpenMP places/proc IDs, and binding/wait/dynamic
environment. It is a compatibility guard, not a complete hardware inventory
or a cryptographic identity of every compiler flag. Exact build flags and
source/binary hashes remain part of experiment provenance. A user-supplied
profile is an explicit performance hint, never a correctness precondition.

Profile header: `SPMV21 1 hex_fingerprint cache_group_bytes long_threshold margin`.
`M regime kernel threads nz_seconds row_seconds barrier_seconds launch_seconds`
stores a compute model; `P threads nz_seconds row_seconds setup_seconds`
stores preparation cost. All costs are finite/nonnegative, team sizes are
bounded, duplicate model keys and malformed input are rejected. Regime 0/1
is a working-set grouping, not evidence that a matrix fits a physical LLC or
that the kernel saturates DRAM. A 10% margin is conservative project policy,
not a confidence interval. Fit residuals and missed predictions must be
reported; the model cannot guarantee improvement on arbitrary inputs.

For fixed repetition R, model compute cost is launch plus R times estimated
max-thread arithmetic/row work and call synchronization. It approximates
first/cached calls together; it does not independently model every cold-cache
effect. Full measured time always includes the actual first call. The CLI
computes the overflow-checked effective R from repeat and flop target before
preparing. A zero-call plan cannot be executed; the CLI avoids both
inspection and a compute team for it. Zero-nnz positive-flop targets fail.

## Selection, validation, and memory

Serial or parallel full validation is chosen independently of computation.
Parallel preparation uses a single team with two worksharing loops; serial
preparation uses ordinary loops. Row validation also collects all8, longest,
and empty-row counts. There is no validation certificate and no omitted
column check. Validation, profile loading/fingerprinting, policy, allocation,
and cleanup remain charged to the task.

For each applicable recorded team/backend, auto estimates continuous row or
nnz+rows partitions. Merge estimates balanced event work, with its separate
synchronization coefficient. A candidate must beat the conservative model
by the profile margin; missing baseline coefficients mean no upgrade.
short8 is legal only after complete verification; it is not automatically
preferred merely because all rows have eight entries. The linear model does
not know the exact set of x addresses and can miss cache/imbalance effects.

`--v21-kernel=auto|original|csr|short8|merge|long` forces a backend.
`--v21-threads=N` forces a compute team within the OpenMP maximum;
`--execution=serial|parallel|auto` and `--partition=rows|work|auto` retain their
roles. original always uses its own static-row scheduling. `--v2-kernel` and
`--serial-threshold` are v2-only options. `--prefetch=0|32|128` is only used by
v2.1 row CSR/short8; merge/packed long rows ignore it.

`--v21-prepare=auto|serial|parallel`, `--v21-cache=0|1`, and
`--v21-fixup=owners|serial` support individual ablations. `--v21-diagnostics`
adds thread-local compute, publication-wait, fixup, and completion-wait
timers on optimized paths; do not mix those timings into normal samples.
Original's internal barrier is not separately instrumented. These are software
timings, not DRAM counters or a proof of the cause of every regression.

Cached row/merge boundaries are bound to the selected team. If the actual
team differs, every thread uses the same uncached complete-row fallback;
there is no partial participation in a merge barrier. This first version
does not recache a changed team. Group fixup assigns each split output row
one owner, reads its fragments in coordinate order, and adds old y once.
Both fragment-publication and call-completion barriers remain.

Metadata is O(T): one `v21_slot` and two `v21_group` capacities per selected
thread, charged to the shared plan budget (default 4 MiB). Allocation failure
or budget exhaustion uniformly falls back to ordinary CSR without slots.
No matrix values/indices are copied. No nonempty-row compression or empty-run
table is implemented in this version: it remains an optional follow-up.

The plan borrows CSR; structural, dimension, storage, or type changes require
explicit rebuild. In-place structural mutation is not detected by a pointer
check. Values/x can change between calls, and are read live. x/y must not
overlap. Prepare/free are serial, execute is collective with equal counters
and parameters, and the same plan/y cannot run concurrently.

## Numerical behavior and method sources

CSR/short8 use local ordered scalar accumulation with contraction disabled;
there is no global fast-math or global vectorization disable. Long rows can
use scalar address loads packed into AVX2, eight accumulators and horizontal
sum. Merge and packed long rows regroup floating-point addition; they require
row-sensitive error checks and are disabled by `--strict-order`. Explicit
original is also rejected with strict-order because its original FP mode is
not the ordered contraction-off reference. Other formats fall back to the
unchanged original implementation. Empty rows still add zero, including
signed-zero behavior. No universal bitwise equivalence is claimed.

* Elafrou et al., [low-overhead CPU SpMV selection](https://arxiv.org/abs/1711.05487),
  III-D/E and IV-D: structural selection and setup amortization; our model,
  coefficients, team set and margin are project adaptations.
* [AOCL expected-call hints](https://docs.amd.com/r/en-US/68552-AOCL-api-guide/aoclsparse_set_-_hint?contentId=_yplp7sQP6BHC7KEXyUokw):
  interface/lifecycle reference, no library dependency.
* Merrill/Garland [CPU merge implementation](https://github.com/dumerrill/merge-spmv/blob/18895571ce9af960ee207dae541b0ffc701ea4bb/cpu_spmv.cpp),
  BSD-3-Clause; original notice retained. Cached coordinates, delayed writes
  and per-output owner fixup are adaptations to f32/int64/y+=Ax.
* AOCL [indexed AVX2 packing](https://github.com/amd/aocl-sparse/blob/d633b58d3cfa266a2a0a8e2fb0f22cc97ee7355c/library/src/include/kernel-templates/kt_l0_avx2.hpp):
  independently implemented method, as in the project's v1 pack control;
  AOCL's FMA, templates and alpha/beta paths were not copied.
* [OpenMP 5.2](https://www.openmp.org/spec-html/5.2/openmpse66.html) provides
  the worksharing/completion rules, not a promise of low synchronization cost.

Unit tests cover live values/x, repeated nonzero y, zero/empty/tail rows,
NaN/Inf/cancellation/subnormal/signed zero, split rows across teams, changed
actual teams, allocation failure, profile parsing/mismatch and call-budget
selection. Benchmark conclusions live in the separately committed experiment
records; this code commit precedes the formal v2.1 comparison.
