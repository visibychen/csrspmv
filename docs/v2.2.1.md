# v2.2.1: complete sparse-index selection and direct reuse

Based on v2.2 (10f6b89). The default backend remains original.

```
./csrspmv input.mtx --kernel=v2.2.1 --repeat=9 -v
```

The original CSR, v2 and v2.2 numerical source files are unchanged. This version prepares plans; it reuses the v2 executor for ordinary work, and the v2.2 executor only for empty runs. The requested policy and selected executor are separate log fields. The main program uses the prepared thread count even for a v2 executor, so a two-thread giant-row plan launches two threads.

Allocation sampling is only a hint. Full validation counts all nonempty rows. If the hint missed an eligible matrix, or its conservative capacity did not fit, a second row-pointer pass builds an exact-length index when the shared budget permits. This extra pass and allocation are charged to preparation. Empty output rows still add +0; values and x are reread every call. Rebuild after CSR structure changes; x and y must not overlap.

Eligibility retains v2.2's rules: at least90% empty rows, longest row at most64, estimated calls at least2, and not a resident serial task. Explicit empty=on bypasses the ratio/calls/small preference, but not validation, length or budget constraints. Empty=off disables indexing of nonzero matrices; the zero-matrix path remains available. The zero-call plan cannot execute unvalidated data.

Index output bounds now use the selected v2 rows/work partition, with continuous disjoint output ownership. An actual-team mismatch collectively takes v2's safe path. Ordinary v2 dispatch and its flop checks are used directly; there is no new numerical kernel or cached Ax.

The default uses serial column checks. Precommit disjoint calibration did not support enabling parallel checks by default. Explicit --v221-validation=parallel uses one team for nonresident nnz>=1048576; row checks and hint filling remain serial. This remains an experimental hypothesis, not a cache-capacity claim. Events>=4194304 delegate v2 completely. Resident and two-giant thresholds retain v2.2 values. No external profile is read, and no global fast-math flags are introduced.

Options (both --name=value and --name value work):

| Option | Default | Ablation |
| --- | --- | --- |
| --v221-policy | guarded | v2: delegate old preparation and execution |
| --v221-empty | auto | off / on |
| --v221-validation | auto (serial) | parallel: experimental team; serial explicitly restores default |
| --v221-balance | auto | rows: equal-row index bounds |

Explicit v2 backend/partition/execution/prefetch settings continue to delegate v2. Forced indexing combined with explicit backend/partition/execution is rejected. Other data types follow the original fallback. Index capacity, retry, known statistics and actual validation-team size are logged; -1 means delegated/uninstrumented, not zero cost.

```
make CFLAGS='-O3 -march=native -g -Wall -iquote src -fopenmp' check
```

The v2.2.1 tests add both observed sampling misses, exact-budget retry, allocation failures, changed x/values, actual-team fallback and parallel-column validation. Old v2 and v2.2 tests remain intact. Performance acceptance is evaluated separately in the materials repository from frozen commits; no speedup is promised by these thresholds.
