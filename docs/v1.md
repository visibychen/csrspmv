# Optional f32 kernels (v1)

The default is still the original CSR dispatcher. All kernels implement
`y += A*x`, once per call, with the original per-call OpenMP barrier. Example:

```sh
make CFLAGS="-O3 -march=native -g -Wall -iquote src -fopenmp"
OMP_NUM_THREADS=12 OMP_PLACES=cores OMP_PROC_BIND=spread \
  ./csrspmv --kernel=sell --sell-chunk=16 --repeat=9 -v matrix.mtx
```

Use `--kernel=original|csr-scalar|csr-pack|sell`. SELL accepts chunk 8 or 16.
No automatic choice, row sorting, giant-row splitting, cached Ax, or changed
thread creation scope is introduced. This implements stages A and B1/B2 of
the course plan. Sorting and merge-based balancing remain subsequent work.

* `csr-scalar`: the same row algorithm, with GCC function-local loop and SLP
  vectorization disabled. Scalar FMA contraction follows the caller's flags.
* `csr-pack`: AVX2 packs eight scalar x loads, accumulates eight independent
  partial sums, then reduces lanes and handles a scalar tail. Long-row
  summation order differs from the original. Check final assembly: an
  intrinsic spelling alone does not prove a particular load instruction.
* `sell`: SELL-C-sigma with sigma=1, identity row order. Each lane owns one
  row, preserving its CSR item order and adding old y only after the sum.
  Slice pointers are int64, columns int32. No row-length or permutation
  arrays are needed. Padding columns use sentinel -1 and masked gathers;
  invalid lanes never read x, including x[0] containing NaN/Inf. Full slices
  have an unmasked fast path. Tail output stores are masked.

The SIMD sources compile with `-ffp-contract=off`, appended locally in the
Makefile. No global fast-math is enabled. SELL uses separate multiply/add;
the original native scalar tail may use FMA. Therefore these modes do not
promise bitwise equivalence for arbitrary floats. Use a suitable forward
error bound; run both with `-ffp-contract=off` when comparing strict item
order. Non-finite values in valid entries retain normal IEEE operations.

Preparation runs serially once after x/y creation. It validates dimensions,
CSR offsets and columns for the optimized types. Unsupported value types
and ISA fall back to the original dispatcher. C=8 requires AVX2; C=16 also
requires AVX512F. Non-x86 builds retain the original/scalar paths. There is
no instruction-set emulation test in this release.

SELL checks slot and byte overflow before allocation. It rejects padding
above 2x, allocation failure, and an extra-memory requirement above the
smaller of `--sell-memory-mib=N` (default 1024 MiB) and half Linux
`MemAvailable`. With no `/proc/meminfo`, only the explicit budget applies.
These are documented conservative policies, not literature-optimal cutoffs.
The availability check is a snapshot and does not inspect cgroup limits;
it cannot guarantee immunity to OS OOM termination or concurrent memory use.
`N=0` forces memory-budget fallback. Inspection itself takes time even on
fallback, so fallback is not advertised as free. All fallback reasons and
allocated extra bytes appear with `-v`.

`spmv_prepare` measures inspection/conversion; the existing
`csr_matrix_int32_spmv` timer measures execution including parallel entry,
exit and iteration barriers, excluding plan free. Process wall time also
includes parsing, CSR construction, output and cleanup. Report all three.
For P preparation time and per-call times T0/T1, the amortization condition
is R > P/(T0-T1), only if T1<T0.

The plan borrows CSR and owns a SELL snapshot. Rebuild after any matrix
value or structural change. x and y may change between calls, must have
matching sizes/types and may not alias. Each thread passes its own flop
counter; all threads of one team call execute. Prepare/free are serial.
No per-call allocations occur. Zero-nnz with positive `--flops` is rejected
instead of the original infinite loop; negative repeat/flop counts are
rejected. Other original types and command-line behavior are preserved.

## Method provenance

This is an independent implementation of published methods; no upstream
source lines were copied and no third-party runtime is required. Reference
repository versions are pinned so algorithm comparisons remain reviewable:

* Kreutzer et al., SELL-C-sigma (2014),
  [paper](https://arxiv.org/abs/1307.6209),
  [DOI](https://doi.org/10.1137/130930352).
* GHOST, BSD-3-Clause, commit
  `22a004dbbfb604d7b04b0bde813c8100d403cfcc`,
  [SELL AVX2 template](https://github.com/RRZE-HPC/GHOST/blob/22a004dbbfb604d7b04b0bde813c8100d403cfcc/src/autogen/sell_spmv_avx2.c.in):
  column-major chunks, independent row accumulators and gather loads.
* AMD AOCL-Sparse, MIT, commit
  `d633b58d3cfa266a2a0a8e2fb0f22cc97ee7355c`,
  [CSR kernel](https://github.com/amd/aocl-sparse/blob/d633b58d3cfa266a2a0a8e2fb0f22cc97ee7355c/library/src/level2/aoclsparse_csrmv_kt.cpp),
  [load/pack templates](https://github.com/amd/aocl-sparse/blob/d633b58d3cfa266a2a0a8e2fb0f22cc97ee7355c/library/src/include/kernel-templates/kt_l0_avx2.hpp):
  block accumulation, scalar x loads packed into vectors, reduction and tail.

New code is GPL-3.0-or-later, consistent with the surrounding project.

## Tests

```sh
gcc -O3 -march=native -g -Wall -iquote src -fopenmp -ffp-contract=off \
 tests/test_spmv_plan.c src/csr.c src/matrix_market.c src/vector.c src/parse.c \
 src/spmv_plan.c src/spmv_csr_scalar.c src/spmv_csr_pack.c src/spmv_sell.c \
 -Wl,--wrap=malloc -lm -o tests/test_spmv_plan
OMP_NUM_THREADS=12 ./tests/test_spmv_plan
```

The test uses long-double references and row-length / sum-absolute-product
error bounds. It covers repeated accumulation into nonzero y, changing x,
short/long/ragged/empty rows, rectangular/zero dimensions, padding with
non-finite x, cancellation/subnormals, invalid CSR, overflow, budget guards,
and each of the three SELL allocation failures. A compatible AVX2 machine
is needed for the allocation injection checks. Full experiment scripts,
sanitizer runs, numerical results and performance data live in the companion
course-materials repository.
