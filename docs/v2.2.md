# v2.2: guarded extensions of v2

This branch starts at v2 `9b652e8`, not v2.1. `csr.c` and `spmv_v2.c` are
unchanged. Default remains original; opt in with `--kernel=v2.2`.
There is no runtime cost profile or fingerprint and no numerical matrix copy.

The CLI computes overflow-checked effective repeat count before preparation.
Zero calls avoid inspection/computation. Other value types use original.
Explicit v2 kernel, partition, execution, threshold or nonzero prefetch settings
delegate to v2. `--v22-policy=v2` disables all guarded extensions.

For at least 4194304 rows+nnz events, prepare/execute are the existing v2
functions, with the same team/kernel/FP settings. Main large uniform SpMV
therefore keeps short8 at the requested team, instead of extrapolating a
profile that changes the backend. Identical source still does not guarantee
identical final addresses/cache state; paired experiments test actual costs.

Below that limit, plain loops fully check row pointers and every column,
collecting all8, longest and empty counts. Original tiny work (32768 events)
stays serial regardless of vector width. The additional conservative serial
window is at most 262144 events and 2MiB logical CSR+x+y bytes. Independent
calibration confirmed these candidates before the code was committed; they
are machine-specific policy guards, not a physical cache-capacity theorem.

Zero nnz uses streaming y+=+0, ignoring unused x width; output up to2MiB stays
serial. For nonzero, a maximum64-row sample may trigger allocation, but only
full validation establishes the actual empty ratio. Auto empty-runs needs
at least90% empty rows, maximum row length64, R>=2, and a bounded allocation.
`--v22-empty=auto|off|on` provides a control. Forced on bypasses the ratio/R
preference but not length, safety, budget or explicit-v2 settings.

The nonempty index table allocates capacity min(rows,nnz) int32 entries,
plus24 bytes of cached bounds per selected thread on this platform. Its full
allocated capacity, including unused entries, is charged to the shared plan
budget (default4MiB). Failure falls back to ordinary v2 kernels. Empty runs
still update every y element with +0; nonempty rows sum in CSR order before
adding old y once. Work is O(rows+nnz), not O(nnz). One completion barrier
remains. Different actual teams uniformly take the uncached v2 row/merge-safe
fallback, never partially participate in incompatible barriers.

Only if the requested-team v2 rule would already choose merge, R>=2,
events<=1048576 and longest>=nnz/4, the compute team is capped at2. The merge
decision is not recomputed from the two-thread average. All other large-tail
cases use v2's work partition and merge implementation. Strict-order disables
split-row regrouping as before; the new empty-run path preserves row order.

Plans borrow CSR; structural/storage/dimension/type changes require rebuild.
Values and x are read live every call; no Ax or R*Ax substitution. Writable y
must not overlap x or matrix storage. Prepare/free are serial and execute is
collective with equal arguments/counters. Zero-call plans cannot execute.

No global fast-math/vectorization disable. New nonempty sums have contraction
off and ordered scalar addition; elementwise empty updates can be vectorized.
The original and v2 automatic SIMD behavior is retained. NaN/Inf/subnormal,
signed zero and row-sensitive error bounds are tested; merge is not universally
bitwise identical to unsplit summation.

Method sources: [PETSc compressed rows, fixed v3.24.0](https://github.com/petsc/petsc/blob/51619389660697cb6ab811d9eb05c4522bec4803/src/mat/utils/compressedrow.c)
for nonempty indexing (method reference, no copied source); [Elafrou CPU
SpMV](https://arxiv.org/abs/1711.05487) for low-overhead bounded specialization;
[OpenMP completion semantics](https://www.openmp.org/spec-html/5.2/openmpse66.html).
The inherited NVIDIA merge implementation and its BSD notice remain in v2
and docs/merge-spmv-LICENSE.txt. Thresholds and continuous-output +0 adaptation
are project choices, not claimed literature optima.
