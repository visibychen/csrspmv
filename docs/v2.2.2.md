# v2.2.2: bounded empty intervals

Based directly on v2.2 (10f6b89). The default remains original.

```
./csrspmv input.mtx --kernel=v2.2.2 --repeat=9 -v
make check CFLAGS='-O3 -march=native -g -Wall -iquote src -fopenmp'
```

The full validated row scan records up to eight empty intervals in fixed plan storage. Automatic selection requires at least90% empty rows, average empty interval length>=1024, longest nonempty row<=64, at least two calls, and a nonresident nonzero task. Too many intervals safely keep the parent policy. Zero matrices retain the parent zero path. Periodic sampling misses outside these limits remain possible in the legacy indexed path.

Each thread owns a continuous rows/work range. It performs current CSR arithmetic in nonempty spans and actual y+=+0 over empty spans, then completes one barrier. The new path retains no allocated index; a parent's speculative table can be allocated, filled and freed during preparation, and all that cost is charged. Inline interval payload is reported separately from dynamic arrays. Actual-team mismatch collectively uses the old v2 row path.

--v222-policy=guarded|v22|v2 selects default preparation or delegates either control. --v222-runs=auto|off|on controls only the new interval path; off keeps parent indexing and zero processing. On bypasses ratio/calls/residency preferences but retains full validation, eight-interval capacity and maximum row length. Forced runs with explicit v2 backend/partition/execution or forced old indexing is rejected. Both --name=value and --name value are accepted.

Original csr.c, spmv_v2.c and spmv_v22.c numerical sources remain unchanged. No cached Ax, changed R, global fast-math, format conversion, or deleted per-call completion. Values/x may change between calls; rebuild on structural mutation and keep x/y non-overlapping. Performance selection is evaluated independently after the implementation commit is pushed.
